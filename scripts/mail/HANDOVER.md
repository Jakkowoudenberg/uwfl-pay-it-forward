# Approval mail delivery — current state

The site now queues one corrected English approval message per approved artwork in
`uwfl_mail_log` with `state=awaiting_sender`. The message is generated by
`netlify/lib/approval-message.js`, uses the actual shipping country, includes the
public NWFA/T&G collection destinations, deadlines and ten rear-side fields, and
keeps Expo selection distinct. Other countries are told to contact UWFL before
shipping. No mass corrections were sent.

The unsafe legacy `panel_approved` Apps Script dispatch has been stopped: its
unverified template previously sent the wrong Florida address. Registration,
contact and other existing notifications continue to use the established sender.
Administrators can download a corrected `.eml` from Mail status and send it using
the UWFL account. Downloading never marks a message as sent or delivered.

Automatic dispatch remains blocked on access to the original Google Apps Script
source/deployment or a verified existing sender supporting exact subject/text.
Do not guess the legacy endpoint contract or send tests to real participants.
Broad retrieval of hosting environment variables was rejected by automatic
approval review because it could expose production credentials; do not retry it.
The connected Drive search did not expose an Apps Script source. No credentials
were retrieved. Restore automatic dispatch only after verifying the exact message
contract and using the existing approved account. Log provider acceptance separately
from mailbox delivery; preserve idempotency and never retry an ambiguous send.

`approval-mail.cjs`, `regional-copy.json` and the fictional `_mail-review.html`
remain design fixtures, not the production sender. Production formatting uses
`approval-message.js` and is tested in `check-release.cjs`.
